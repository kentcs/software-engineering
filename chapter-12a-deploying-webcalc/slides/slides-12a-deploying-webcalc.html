Deploying WebCalc

A tested application on a server

Gregory S. DeLozier, PhD

The deployment target

Setting Value
Server webcalc.kentcs.org
Account and directory webcalc, /home/webcalc
Port and Screen session 8080, webcalc

Run the tests locally

In code/webcalc/, with the test environment active:

python -m pytest -v test_calculator.py
python -m pytest -v test_main.py
python run_browser_tests.py

Expected: 27 tests, 12 tests, 12 scenarios pass.

Three methods, three kinds of evidence

Method What it reaches
Direct unit tests Calculator operations
NiceGUI simulated user Interface event handling
behave and Selenium Real browser interaction

The release gate

deploy:
  needs: test
  runs-on: ubuntu-latest
  environment: production

All three test jobs must pass before the server changes.

Deployment credentials

In GitHub: Settings > Environments > production

Secret Purpose
DEPLOY_SSH_KEY Authenticate the client
DEPLOY_KNOWN_HOSTS Verify the server

Copy the runtime files

scp main.py calculator.py requirements.txt \
  webcalc@webcalc.kentcs.org:/home/webcalc/

The workflow adds strict SSH options.

Three files. No compilation step.

Run the remote script

ssh webcalc@webcalc.kentcs.org \
  'bash -s' < scripts/deploy.sh

Install dependencies, stop the old session, start WebCalc.

Start a detached Screen session

screen -dmS webcalc bash -c \
  'exec .venv/bin/python main.py \
  >> /home/webcalc/webcalc.log 2>&1'

The app survives SSH logout. It does not restart itself after a reboot.

Run the deployment

In the configured WebCalc repository:

gh workflow run release.yml --ref main
gh run list --workflow release.yml --limit 5

Expected: three test jobs pass, then deployment succeeds.

Inspect the running app

ssh webcalc@webcalc.kentcs.org
screen -ls
tail -f /home/webcalc/webcalc.log

Open the public page: 2 + 3 = 5.

The cost of a direct update

Files change in place.

Restart causes brief downtime.

No retained release or automatic rollback.

Change one assertion in test_calculator.py. Push.
